## Pinned repos (how I’d curate yours)

| Keep pinned | Why |
|-------------|-----|
| **Your best original app** (e.g. a real project, not a tutorial fork) | Shows *you* as the author and what you ship. |
| **One strong API / backend or infra repo** | Signals depth beyond the frontend. |
| **A polished UI or design-system adjacent project** | Demonstrates craft and attention to detail. |
| **Optional: one “learning / experiments” repo** | Shows curiosity — label it clearly in the repo description. |

**Depin or unpin** generic forks (e.g. large “awesome-*” lists, duplicate tutorial repos) unless you actively maintain them — they dilute the story. Replace with repos that have **good READMEs**, **screenshots or demos**, and **clear tech tags**.
